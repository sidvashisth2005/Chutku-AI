# Chutku 20×: the plan

> Approved by the owner 2026-11-10. Progress ticks and the weekly scoreboard are at the end.

## Context
The owner (2026-11-10) wants Chutku to be **20 times better from the user's point of view**. A user can ask
anything, and getting it done must feel like a cake walk. Chutku is the assistant: it must make life easier and
never add work: no questions, waiting, failures or hangs the user has to deal with. Everything (resources,
structure, time, practice, thinking) is planned and followed, so we never run blindly.

This plan replaces the research plan that was in this file. That research (problems list, AirLLM, GitHub projects)
lives in `docs/PROBLEMS_AND_RESEARCH.md` and `docs/BRAIN_2_PLAN.md` on branch `claude/brain-2`, and this plan uses
it as its idea bank.

## 1. What "20× better" means: one number

"Better" is measured as **burden**: everything the user has to do or put up with that a perfect assistant would
spare them.

**Burden per 100 requests (B100)** is the sum of:

| Weight | What counts |
|:-:|---|
| 5 | Each failed or half-done request |
| 3 | Each wrong action (wrong target, wrong app) |
| 2 | Each question or confirmation the user had to answer |
| 1 | Each 5 s the user waited beyond doing it by hand |
| 20 | Each hang or freeze |

**20× = B100 divided by 20**, measured weekly from the real logs and the scenario bank. Smaller sub-targets support
it.

## 2. The eight pillars

Each pillar is a promise to the user.

1. **It works:** the right thing, fully done, first time.
2. **It never burdens:** it does not ask what it can work out; asks once, then remembers; never repeats a
   question.
3. **It's fast:** a repeat task beats doing it by hand; a new task is no slower than by hand.
4. **Anything goes:** any app, any phrasing, Hindi, English or Hinglish, multi-step. Generalise; don't add one
   regex per phrase.
5. **It knows me:** this session, past sessions, the screen, people, chats, places, habits.
6. **It never freezes and never lies:** no hangs; it says honestly what happened.
7. **Easy from minute one:** install to first success in ≤ 3 minutes; discoverable; voice-first; Hindi.
8. **It gets better by itself:** every failure becomes a test; it practises at night; the morning report goes to
   Telegram.

Safety stays as it is: no system damage, passwords never stored or sent, deletes go to the Recycle Bin after one
Yes, and UAC for admin tasks.

## 3. How we work: structure, so we never run blindly

### The single source of truth
- `docs/TWENTY_X_PLAN.md`: this plan, with a tick list per phase.
- The weekly scoreboard section is generated by `scripts/scoreboard.py` from the logs, not written by hand.

### The flywheel (every working session runs this loop)
1. **Measure.** `scripts/scoreboard.py` reads `data/conversations.jsonl` and `data/actions.log.jsonl` and prints:
   - B100;
   - per-tool success;
   - asks;
   - hangs;
   - latency per tier.
2. **Pick.** Take the biggest burden item on the board. Highest B100 points first; never what is merely
   interesting.
3. **Reproduce.** Write a failing test from the real turn and add the turn to the scenario bank.
4. **Fix the class, not the phrase.** Fix the root cause for a whole family (for example "focus lost before
   typing"), not one sentence.
5. **Verify.** Run, in order:
   - the unit tests;
   - `scripts/check_stages.py`;
   - one live path on this PC;
   - a negative case for safety items.
6. **Record.** Add the evidence to `IMPLEMENTATION_STATUS.md`, commit and push to main.
7. **Practise.** That night the scenario bank re-runs, so regressions are caught by morning.

### Rules of thinking (from AGENTS.md and the Karpathy principles, applied to this plan)
- **No feature without a number** it moves on the board.
- **Never break a working mode.** The Gemini Live voice stays the default.
- **Regex is only a cache.** Understanding comes from the task card (Phase 4); `quick_intents` only speeds up
  phrasings already proven.
- **Breadth first:** many small working fixes beat one deep dive (the owner's rule).

### Roles (cheap on tokens)
| Role | Who | Does what |
|---|---|---|
| CEO, final say | The owner | Decides; does the UAC clicks and phone checks |
| Lead engineer | This PC session | All coding and live tests here; web Claude is paused per the owner |
| Helper agents | Explore / Plan agents, only for wide searches or design | Each prompt is logged verbatim in `docs/AGENT_PROMPTS.md` |
| Night worker | Chutku's own Night Shift: local and free models | No Claude tokens used |

### Tokens and money
- **Zero-cost measurement.** The scoreboard, scenario runs and night practice are plain scripts or Chutku's own
  free models; Claude tokens go only to fixes.
- **Releases** are built on this laptop with `scripts/release_local.ps1` (GitHub Actions is unpaid).

## 5. Phases, time and exit gates

Times assume one or two working sessions a day.

### P0: Measure and finish what's open (days 1–2)
1. Finish the WhatsApp current-chat change already written (uncommitted) in `chutku/tools/apps_extra.py`:
   - What it adds:
     - `is_current_chat`;
     - `_send_to_current_chat`;
     - `_open_pane_for`, which runs the already-open check before any Esc (fixes KitKat open in Locked chats);
     - the `to='current chat'` tool description.
   - Tests to write:
     - phrase detection, positive and negative;
     - "no chat open" fails closed;
     - the named chat already open in the Locked chats view is reused without Esc.
   - Live dry-run: `scripts/verify_whatsapp.py`. A real message only with the owner's OK.
2. Log `seconds`, `tier` (reflex / replay / one-shot / deliberate), `asks` and `outcome` on every turn in
   `conversations.jsonl`. The hook point is where turns are appended today.
3. `scripts/scoreboard.py` computes B100 and the per-tool table above, and prints a markdown block.
4. **Scenario bank v1** (`tests/scenarios/bank.jsonl`):
   - every failed, clarify or cancelled real turn;
   - 100 sampled successes;
   - each with an expected tool and arguments plus a pass check.
   - A runner replays it in plan mode with no side effects. It extends the existing practice
     (`chutku/practice`: `nightly`, `best_of_n`).
5. **Gate:** baseline B100 is recorded in `docs/TWENTY_X_PLAN.md`.

### P1: It works, stop the bleeding (week 1)
Fix the top failing tool classes. Each fix gets tests from the real failures.

1. **WhatsApp send and open chat:**
   - current chat, Locked chats pause-for-unlock and resume;
   - the header confirm for short names (the UB failures);
   - search box not found;
   - fuzzy names from the mind graph.
2. **Spotify search, play playlist and play artist:** 0 of 15 today. Find the root cause and use the Web API or
   the URI route.
3. **`screen.act_on_visible`:** item-versus-playlist type matching is too strict; quoted names fail.
4. **`apps.launch`:**
   - wait for the real window (UWP and splash screens);
   - fuzzy name to installed app, so it never says "no installed app matches" when a near match exists.
5. **`apps.quit`:** strip "in brave", "active", "current"; prefer the foreground app.
6. **Focus before typing** (`keyboard.type_text`): re-find the window by title and retry focus once.
7. **`files.open`:** resolve "that file" from recent files and history, and search the drive index (`drive-index`)
   before saying it does not exist.
8. **Hangs:**
   - move `refresh_habits` / `recall.hidden_turns` and image describing off the HTTP loop, with time limits;
   - after sleep/resume, the watchdog restarts cleanly instead of stalling.
9. **Gate:** every listed tool reaches its target on the scenario bank and on one live path; hangs are 0 for 3
   days.

### P2: It never burdens (week 2)
1. **Approval audit.** Find why 86 confirmations happened in owner mode. Ask only for:
   - R4 actions;
   - deletes (one Yes);
   - unknown recipients;
   - first-time risky steps.

   Remember each answer (`approval_memory`).
2. **Make the reversible ones undoable instead of asked:** file write, move and create directory get an undo
   toast.
3. **Resolve, don't ask:** missing city comes from location (done), missing app is the fuzzy match, missing chat
   is the current or last chat, missing time is the next sensible slot. Ask only when two options are equally
   likely, in one line.
4. **No chit-chat question tails:** persona rule; replies end with the result, not "aur kuch?".
5. **Approvals survive voice:** an approval does not expire while Gemini Live is speaking; say "haan" to approve.
6. **Gate:** asks ≤ 2 per 100 action turns; no question repeated across sessions.

### P3: It's fast (weeks 3–4)
1. A per-tier latency report from P0's logs.
2. **Replay cache (tier 1.5, the muscle-mem pattern):**
   - a clean success is saved as steps with checks;
   - the next time it replays with no model; a failing step goes back to the planner;
   - turn on experience replay for cloud-first sessions (only 12 of 87 rows can replay today).
3. **Multi-provider router:** Gemini → Groq → Cerebras → OpenRouter, failing over on quota; prompts kept small.
4. **Speculative multi-action** (the UFO² idea): several steps per model call.
5. **Run independent steps in parallel**, and start the app while the plan is still being thought out.
6. **Gate:**
   - p50 ≤ 2 s for repeat tasks;
   - new single-app tasks ≤ 8 s;
   - ≥ 70% of real asks served by tier 1 or 1.5.

### P4: Anything goes (weeks 4–6)
1. **Understand step:** one cheap call turns the request plus context into a task card listing every part. The
   "finish every part" checker marks the request done only when all parts pass.
2. **Generic screen loop:** look → act → verify for any app.
   - Uses UIA where it works.
   - Vision fallback (spike: OmniParser or UI-TARS-2B on the GPU; pick the one with better accuracy per second)
     for WhatsApp-like apps that UIA can't see.
3. **Locks:** on a lock screen or password box, pause, ask the owner to unlock, then resume from that step. Never
   type passwords.
4. **App atlases learnt automatically** from practice runs, not hand-written (extends `chutku/apps/lab`).
5. **Gate:** the "new" scenario set (50 tasks never seen before, from the owner's style) reaches ≥ 85% full
   completion.

### P5: It knows me (weeks 6–7)
1. **Context pack** for every brain call:
   - the last turns;
   - related past sessions (history search);
   - the mind graph;
   - the foreground window summary.
2. **Time-aware mind graph** (Graphiti ideas): facts with valid-from and valid-to dates, plus corrections that
   are remembered.
3. **Gate:** a references test set ("usme", "wahi", "kal wala", "the one I opened") at ≥ 90%.

### P6: Easy from minute one (weeks 7–8)
1. Install to first success in ≤ 3 min. Check this with a fresh Windows user account on this PC.
2. "What can I say": shown from the user's own apps on first run, plus a voice tour.
3. Hindi UI strings and Hindi replies; an eco mode on battery.
4. Opt-in failure reports with private data removed, and a "go back to the previous version" update option.
5. **Gate:** a fresh-account run is timed and recorded; zero dead ends in onboarding.

### P7: It gets better by itself (from week 1, continuous)
1. Night Shift runs the scenario bank, live practice in `D:\ChutkuPractice` and best-of-N on misses.
2. The morning Telegram report: B100 trend, new failures, what was learnt.
3. Weekly LoRA once there are enough logs (the approved plan); keep it only if it scores better.
4. AirLLM night-teacher spike: kept only if it beats the free cloud tier.

### Release rhythm
At the end of each phase, if the scoreboard improved and nothing regressed:
1. Release with `scripts/release_local.ps1`.
2. Update the release README and its screenshots.
3. Send a Telegram note to the owner.

## 7. Verification (every change and every phase)
- **Unit tests:** `.venv\Scripts\python -m unittest`, plus `scripts/check_stages.py`.
- **Scenario bank** run in plan mode: pass rate per phase gate.
- **One live path on this PC** per user-facing change (`scripts/live_check.py`): time in seconds plus an
  independent check that the answer is right.
- **Safety negative cases:** damage refused; a lock pauses; a password is never typed; an unknown recipient is
  asked.
- **`scripts/scoreboard.py`** before and after: B100 must fall. A phase is not done until its gate number is met.
- **Evidence** goes into `IMPLEMENTATION_STATUS.md` in the same commit; push main after each slice.
